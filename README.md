La aplicación va a ser un SaaS multi-tenant que permite a un cliente crear un chatbot experto y personalizable basado en sus propios documentos, sin entrenar modelos, usando un enfoque de Hosted RAG con OpenAI. El producto va a tener dos perfiles principales: administradores (o editores) que cargan y gestionan el conocimiento del bot, y usuarios finales que inician sesión y conversan con el asistente para resolver dudas y obtener respuestas respaldadas por las fuentes cargadas. En tu portfolio el ejemplo principal va a ser un bot experto en componentes de PC (descripciones, compatibilidades, armado, troubleshooting y recomendaciones), pero la misma plataforma va a permitir que cada cliente defina su propio tema, tono, idioma, reglas y estilo de respuesta a través de configuraciones guardadas en base de datos.

A nivel técnico, el frontend se va a desarrollar en React y va a ofrecer una interfaz de autenticación, un panel de administración de bases de conocimiento y documentos, y una interfaz de chat tipo “ChatGPT” con soporte para streaming y una sección de fuentes/citas. El backend se va a construir con ASP.NET Core en .NET 8 (C#) siguiendo una arquitectura por capas, separando controllers y filtros, servicios de aplicación con validaciones y casos de uso, dominio con entidades e interfaces, e infraestructura para persistencia, storage y la integración con OpenAI. La persistencia principal va a ser MySQL para almacenar usuarios, tenants, roles, configuraciones del bot por cliente o por base de conocimiento, documentos y sus estados de indexación, sesiones de chat, mensajes, citas asociadas a cada respuesta y eventos de uso para control de costos y límites por plan. Para el almacenamiento de archivos originales se va a usar un storage externo (por ejemplo Azure Blob o S3; en desarrollo se puede usar almacenamiento local), de manera que los documentos puedan visualizarse, versionarse y borrarse correctamente independientemente del índice semántico.

El “aprendizaje” del bot se va a implementar con Hosted RAG usando OpenAI: cuando un administrador sube un archivo (PDF, PPTX, DOCX, etc.), el backend lo guarda en storage y además lo registra en OpenAI para que quede indexado dentro de un vector store asociado a ese tenant y a esa base de conocimiento. La plataforma va a manejar un vector store por tenant para aislar datos entre clientes de forma simple y segura, y la base de datos va a guardar el identificador del vector store y el identificador del archivo en OpenAI, junto con el estado del documento (subido, indexando, listo o fallido). Una vez que el documento queda listo, el chatbot puede consultarlo mediante la herramienta de búsqueda de archivos de OpenAI en cada interacción, recuperando fragmentos relevantes y generando una respuesta anclada a esas evidencias. Esto permite que el bot sea consistente y auditables, mostrando citas o fuentes en cada respuesta cuando corresponda, y evitando inventar información cuando no haya respaldo en los documentos cargados.

El flujo de uso empieza con el inicio de sesión: el usuario se autentica con email y contraseña, el backend valida con bcrypt y devuelve un JWT para autorizar las llamadas posteriores. Una vez autenticado, un administrador accede al panel de gestión de conocimiento donde puede crear o seleccionar una base de conocimiento, subir documentos y ver su estado de indexación; durante este proceso el sistema registra quién subió cada documento, cuándo lo hizo, y mantiene la relación con el tenant y la base de conocimiento correspondiente. Luego, un usuario final entra al chat, elige la base de conocimiento habilitada para su rol y abre una sesión de conversación; al enviar un mensaje, el backend construye la solicitud a OpenAI incluyendo las reglas de comportamiento configuradas para ese cliente (por ejemplo tono, idioma, nivel técnico y políticas como “si no hay evidencia en los documentos, indicarlo explícitamente”), y habilita la búsqueda en el vector store de esa base de conocimiento para recuperar el contexto pertinente. El backend guarda en MySQL el mensaje del usuario, la respuesta del asistente, los identificadores de la interacción y las citas devueltas, y el frontend renderiza la respuesta en tiempo real junto con un panel de “fuentes” que permite abrir el documento original y ver el fragmento citado. Además, el sistema registra métricas de uso (tokens, modelo, tipo de operación) para poder aplicar límites por plan y estimar costos, lo que habilita monetización con planes Free/Pro/Team más adelante.

En resumen, la aplicación funciona como una plataforma donde el valor principal es que cada cliente puede personalizar su chatbot experto y alimentarlo con su documentación, y los usuarios pueden obtener respuestas confiables con trazabilidad a las fuentes. Las tecnologías centrales van a ser React para la interfaz web, ASP.NET Core .NET 8 en C# para la API, MySQL para persistencia y multi-tenancy, un servicio de storage para los archivos originales, y OpenAI con Responses API y File Search/Vector Stores para la capa de RAG hosteada que indexa documentos y permite recuperación semántica y por palabras clave en cada consulta.
